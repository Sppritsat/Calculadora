## 🎯 Primeros Pasos para Nuevos Colaboradores

### Día 1: Configuración

1. **Lee el README**
   ```bash
   # Abre y lee README.md
   ```

2. **Configura tu entorno**
   ```bash
   # Sigue las instrucciones en SETUP.md
   git clone https://github.com/TU-USUARIO/Calculadora.git
   cd Calculadora
   ```

3. **Prueba la aplicación**
   ```bash
   # Abre index.html o usa un servidor
   python -m http.server 8000
   ```

### Día 2: Familiarización

1. **Explora el código**
   - Revisa la estructura del proyecto
   - Abre los archivos HTML, CSS y JS
   - Ejecuta la aplicación y prueba sus funciones

2. **Lee CONTRIBUTING.md**
   - Entiende el proceso de desarrollo
   - Conoce las convenciones de código
   - Aprende sobre pull requests

3. **Revisa el ROADMAP**
   - Busca tareas marcadas como "good first issue"
   - Elige algo pequeño para empezar

### Día 3+: Contribuir

1. **Crea tu primera issue**
   - Reporta un bug que encuentres
   - O sugiere una mejora pequeña

2. **Haz tu primer pull request**
   - Corrige un error tipográfico
   - Mejora la documentación
   - Agrega un comentario al código

## 💡 Consejos para Trabajo en Equipo

### ✅ Buenas Prácticas

1. **Comunica constantemente**
   - Informa sobre tu progreso
   - Pide ayuda cuando la necesites
   - Responde a mensajes de compañeros

2. **Sé respetuoso**
   - Acepta críticas constructivas
   - Ofrece feedback amable
   - Reconoce el trabajo de otros

3. **Documenta todo**
   - Escribe comentarios claros
   - Actualiza documentación
   - Describe tus PRs detalladamente

4. **Prueba antes de compartir**
   - Verifica que tu código funciona
   - Prueba en diferentes navegadores
   - No rompas código existente

5. **Haz commits pequeños**
   - Commits frecuentes y específicos
   - Mensajes descriptivos
   - Un cambio a la vez

### ❌ Errores Comunes

1. **No comunicarse**
   - No desaparecer sin avisar
   - No trabajar aisladamente
   - No ignorar mensajes

2. **Cambios muy grandes**
   - No hacer mega-PRs
   - No cambiar muchos archivos a la vez
   - No refactorizar todo

3. **Saltarse procesos**
   - No hacer commits directos a main
   - No saltarse revisión de código
   - No ignorar las guías de estilo
